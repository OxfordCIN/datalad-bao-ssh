# DataLad extension for OpenBao managed SSH certificates

This repository contains an extension that allows the use of short
lived SSH certificates issued by an OpenBao server with [DataLad](https://datalad.org).

## How it works

The extension will setup your SSH configuration such that connections
to the DataLad services (Git and RIA servers) will ensure you have, and
present a SSH certificate identifying you. This certificate intentionally
has a short-lifetime, to minimise the risk of it being compromised.
On attempting an SSH connection to one of the configured end points you
will be prompted to log into an [OpenBao](https://openbao.org) server.
This server can then issue SSH certificates that the Git and RIA endpoints
have been configured to trust to identify you.
Ordinarily you only need to run this once, unless something in your
environment changes (e.g. a server address needs to be updated) or
if your ~/.ssh/config file is lost.

## Prerequisites

Ideally this script can utilise the [`bao`](https://openbao.org/downloads/)
client program to handle your logins, but can fall back to using cURL for
**some** authentication backends - if it can't find either of then the script
will fail.
In all cases, the command 'jq' is required on you computer. This is pre-
installed on macOS 15+, but older macOS will need to install it via e.g.
Homebrew or MacPorts. It is likely to be already installed on Linux platforms
(including Windows Subsystem for Linux) but if not use the package manager/
software centre to install it.

If your system already has the `bao` client installed and you wish to use it
then make sure that your terminal can find it. This might involve loading
an environment module or ensuring the system `bao` is in your software
search `PATH`. Examples of installation methods for `bao` include MacPorts,
Homebrew, RPM, apt.
If it does not then the setup command will attempt to install Bao in the folder
`.baobin` in your home folder (see below for how to change this).

## Installation

This plugin can be installed from Pypi with the command:

    pip install datalad-bao-ssh

or

    pixi add --pypi datalad-bao-ssh
    pixi install

or

    uv pip install datalad-bao-ssh

or

    conda config --append channels conda-pypi  # If you haven't already enabled conda-pypi
    conda install datalad-bao-ssh

## Service Configuration

The command will attempt to download some basic configuration provided
by the server referenced in the DataLad setting
'datalad.bao-ssh-config-url' (see :ref:`Configuration`).
DataLad service administrators should make available at this URL a JSON
format file (see :ref:`JSON Configuration`) that provides the main
configuration for the service.
If this site is unavailable you will be prompted for this configuration
information (see :ref:`Configuration`).

After initial configuration you will be prompted to enter your user name
on the OpenBao server (which must match that on the RIA and Git endpoints).

With this information your SSH client configuration will be updated to
run a script each time you connect to the RIA/Git hosts.

## Usage

When you carry out a DataLad command that requires SSH access, the script
generated by this extension will ensure that you have a valid short-term
SSH certificate. Where you don't you will be prompted to log into the
authentication server again to obtain a new one.

Some authentication backends will prompt for passwords (e.g. `ldap`) and
others may ask you to visit a website to continue with the login
(e.g. `oidc` - OpenID/Entra etc).

## Maintenance

When called with the option `--update`, this plugin will check for updates
to itself, DataLad (both from the PyPi repository) and the OpenBao `bao`
software (where it installed this into your home folder). If updates are
installed, you will be advised if you need to run the update command
again to complete the upgrade process.

It is recommended that you run this on a regular basis to ensure you are
using the latest versions of the software.

## Configuration

This extension has two configuration options which can be set with

    git config --set \<option> "\<value>"

* datalad.bao-ssh-config-url: URL of JSON configuration file
* datalad.bao-ssh-bao-install-dir: Path to install 'bao' client in -
   defaults to '.baobin' in the user's home folder

If the configuration can't be downloaded from the configured web server
the script will prompt you to consider whether you need a VPN connection
to access it:

  *Would you like to quit so that you can connect to a VPN and try again?*

Answer `y` to quit if this is the case, connect to your VPN or institutions
network and try again.

Please ask your DataLad/OpenBao administrator for the answers to the
following questions.

* *OpenBao role that allows signing of SSH certificates*
* *OpenBao 'principal' that identifies users of DataLad*
* *SSH certificate type to generate* (only change if you know that you need a different type)
* *Hostname of the OpenBao authentication server*
* *Port that OpenBao is listening on*
* *Authentication backend URL component on OpenBao server* (e.g. `ldap` or `oidc`)
* *Suffix to remove from the OpenBao account name so that it matches the username known to the RIA and Git services (if required)* (will only be asked if using `oidc` - a blank entry is acceptable)
* *Does your remote git server(s) use a per-user username (Ordinarily GitLab/Hub server endpoints will have any required username encoded into the repository so this will probably be 'no')*

You then need to enter the RIA and Git service host names - again, your
administrator can provide these details. Provide the servers, one per line and
press 'Return' on an empty line when finished with that server type.

Example questions...

* *Enter DataLad RIA endpoint host name (hit return to end)*
* *Enter DataLad GitLab/Hub host name (hit return to end)*

## JSON Configuration

The web-available JSON configuration needs the following keys, equivalent
to the questions asked without it:

| Key | Purpose |
| -- | -- |
| ROLE | OpenBao role for the signing process |
| PRINCIPAL | The generic principal to apply - used by Git services to filter users |
| CERTTYPE | SSH certificate type - see `ssh-keygen` for allowed values |
| BAOHOST | Hostname of the OpenBao server |
| BAOPORT | Port OpenBao is listening on |
| BAOAUTH | Authentication plugin to use |
| BAOUSERSUFFIX | If your auth username has, for example, a domain postfixed then set this to this suffix. The SSH certificate identity will have this stripped from the username |
| GIT_REQUIRES_USERNAME | If your Git server provides per-user accounts set this to true |
| GIT_SSH_HOSTS | List of hostnames for your Git server hosts |
| RIA_HOSTS | List of hostnames for your RIA hosts |

## API

### High-level API commands

* bao_setup
  Arguments:
  * update_bao (optional, boolean) - check for and update 'bao' client

### Command line reference

Run this command to setup your SSH environment to create and use short-lived SSH certificates for authentication to your DataLad remotes.

Option arguments:

* `--update` When provided, will check for and update the signing script and the version of the 'bao' tool. For system-wide 'bao' installations this will only update the signing script.
